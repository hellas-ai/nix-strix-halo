`0003-bootstrap-pollerr-so-error.patch` lets POLLERR-only connect completion reach the existing SO_ERROR handling. It retains the existing retry policy for ECONNREFUSED/ETIMEDOUT, failure for other errors, and all unrelated poll branches. The saved v2 arm remains failed. The underlying asynchronous error is unassigned because its SO_ERROR was not read.

Run `python3 -B pkgs/mscclpp/tests/socket-pollerr-cpu.py` locally. The test pins the exact v0.9.0 source, applies the patch with zero fuzz/offset, and compiles the actual baseline/patched method, actual Socket declaration and host exception definitions. Constructor and poll/getsockopt/close/socket/usleep are explicit CPU surrogates; they make no network calls. Seventeen cases cover the observed early throw, retryable and fatal synthetic SO_ERRORs, read failure, IPv6 retry, and unchanged writable/timeout/syscall/hangup/invalid-event branches. Both executables depend on standard host libraries only. This is a method-level qualification, not a complete bootstrap, GPU, RDMA or package-build result.

Integration should append 0003 after the independent 0002 traffic-class patch in `pkgs/mscclpp/default.nix`; this commit deliberately leaves that shared patch list to root integration. No native ABI or collective arithmetic changes. One existing limitation is retained: the retry branch recreates its socket without reapplying the constructor's nonblocking flags. The test does not qualify real reconnect timing or descriptor flags. Future paired bootstrap execution remains root-owned under its existing bounds and health/cleanup gates.
